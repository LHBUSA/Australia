COUNTRY API ARCHITECTURE

The endpoint resolves the property. The Australia graph explains what it means.

PropData Australia is not a national parcel table with state labels painted on top. G-NAF provides the national address spine; cadastral identity is state or territory native; geometry and legal identifiers follow those source systems; and every promoted layer keeps its own coverage and provenance. The application sees one Australia scope while the data contract remains honest about where the underlying truth came from.

01 · RESOLVEAddress / coordinates / native ID

Start from the strongest identifier your product actually has.

02 · ROUTEJurisdiction-aware identity

Determine which state or territory property system governs the resolved property.

03 · ATTACHCadastre + geometry

Attach promoted lot, parcel or block identity and source geometry where certified.

04 · PRESERVENative semantics

Retain PFI/UFI, PID, volume/folio, block/section/division and other source meaning.

05 · GOVERNCoverage + provenance

Keep match, layer availability, source dataset and source revision independently visible.

06 · DELIVERREST / MCP / bulk / custom

Use the same source-aware country model through the delivery channel your product needs.

07 · REFRESHMaintain national baselines

Promote and refresh source layers behind the contract rather than shipping a one-off file.

08 · EXPANDJurisdiction depth without integration churn

Certified state depth can grow without forcing a new country integration.

Core AU rule: national address identity and jurisdiction-specific cadastral enrichment are different layers. A valid Australia property match does not imply every state-native cadastral or geometry layer is available for that property.

AUTHENTICATION

REST keys stay on the server. MCP uses OAuth.

Direct REST requests use the x-api-key header. Store production keys in trusted server, worker or edge secrets. Do not put a PropData key in URLs, browser bundles, screenshots, repositories, analytics or logs.

ENVIRONMENT
PROPDATA_API_KEY=pd_live_...
PROPDATA_API_BASE=https://propdata-api-worker.sales-fd3.workers.dev
OAuth MCP is separate. Compatible AI clients should use the PropData OAuth MCP authorization flow. Do not paste a static REST API key into an MCP chat or client authorization flow.

IDENTITY MODEL

National address identity first. Jurisdiction-native cadastral identity second.

G-NAF provides the national address spine. Once the property can be routed into a certified jurisdiction layer, PropData preserves the source-native cadastral model rather than forcing it into a U.S.-style parcel schema.

SPATIAL PROPERTY CONTRACT

Geometry is a promoted source layer, not a universal assumption.

Australian property geometry follows jurisdiction source systems. Where promoted, the geometry route and coordinate resolver let applications connect point-based workflows to certified parcel, lot or block context. Where geometry is not promoted, PropData does not manufacture a boundary from another layer.

source geometry

Use the published parcel / lot / block polygon where that jurisdiction has passed promotion gates.

coordinate containment

Resolve WGS84 latitude/longitude into containing property context where coverage supports it.

match semantics

Read exact-source, spatial or other returned match signals independently from HTTP success.

coverage state

Distinguish absent geometry from a parcel that truly has no returned polygon.

RESPONSE HANDLING

Build around explicit identity, coverage and provenance.

Australian integrations should not assume every jurisdiction emits the same source fields. Treat the returned envelope as authoritative and model optional jurisdiction-specific enrichment separately from successful base identity.

ILLUSTRATIVE AU RESPONSE CONCEPT
{
  "country": "AU",
  "jurisdiction": "VIC",
  "match_level": "source_native",
  "coverage_status": "live",
  "property": {
    "...": "promoted jurisdiction fields"
  },
  "provenance": {
    "source_name": "jurisdiction source",
    "source_dataset_id": "source dataset",
    "source_revision": "revision"
  }
}
Illustrative, not universal. This shows the design principles of the AU contract. Preserve the exact response envelope and fields returned by the live production route for the resolved property and jurisdiction.

STATE-NATIVE SEMANTICS

Normalization should not erase meaning.

The point of a country abstraction is not to destroy the underlying source model. PropData provides stable access while still preserving the identifiers, geographic/legal structures and revision context needed by serious downstream systems.

DO NOT GUESS

Match, coverage and provenance are separate signals.

match_level

How the input resolved: address, coordinate, source-native identity or another explicit method returned by the route.

coverage_status

Whether the requested AU source or enrichment layer is available for the resolved property.

jurisdiction

The state or territory property system governing the deeper source-native contract.

source / provenance

Where the fact originated and which dataset or revision supports it.

null / unavailable

Missing source truth remains missing. Do not convert absence into an equivalent or favourable claim.

identity vs enrichment

A valid national address/property identity can survive even when optional state-native cadastral depth is unavailable.

Coverage states

StateMeaningApplication behaviour
baseline_completeCertified source baseline reconciled to the production checkpoint.Safe to treat the promoted layer as production coverage for its stated scope.
expandingA source or jurisdiction layer is actively being built or refreshed.Do not assume universal property-level availability.
partialBase identity is valid but one or more requested layers are absent.Preserve the valid base result and handle enrichment independently.
unavailableNo verified source truth exists for the requested layer or input.Keep the result unknown; do not synthesize an equivalent field.
SOURCES, RIGHTS & PROMOTION

Authoritative sources in. Governed property infrastructure out.

PropData operates the ingestion, normalization, jurisdiction routing, canonical identity, geometry processing, coverage semantics, source revision handling, quality gates and production delivery above the Australian source systems. The country contract is designed to expose what has actually been certified — not what we hope to add later.
